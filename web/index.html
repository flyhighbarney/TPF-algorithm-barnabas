What this demo is doing

For each color channel, two rounds of: 2D permutation → key-dependent S-box → 2D parallel-prefix XOR diffusion, followed by cross-channel RGB entanglement and an HMAC-SHA256 tag. 

plaintext RGB
      │
      ▼  for each channel, ×2 rounds:
  ┌─ Fisher–Yates row/col/intra-row permutation
  ├─ key-dependent S-box (8-bit non-linear substitution)
  └─ row + column + full-image prefix-XOR diffusion
      │
      ▼
  cross-channel RGB entanglement (XOR at key-derived rotated offsets)
      │
      ▼
  HMAC-SHA256(ciphertext) — integrity tag

Performance note

This page is a pure JavaScript port; the original implementation has a C core that runs ~63× faster. Browser encryption of a 256×256 RGB image takes a couple of seconds. Stick to ≤ 512×512 unless you have patience.

Limitations

  • No formal security proof; no public cryptanalysis.
  • Linear (over GF(2)) diffusion layer.
  • 128-bit key space.
  • Plaintext-dependent keying → image hash must travel with the ciphertext.
  • Image-only; not a general-purpose block/stream cipher.
